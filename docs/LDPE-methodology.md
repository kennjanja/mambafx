# LDPE — Last-Digit Prediction Engine: methodology summary for expert review

Source of truth: `src/ldpe/engine.js` (pure statistics, no DOM/network), `src/ldpe/persist.js`, `src/ldpe/exec.js`, `src/ldpe/bridge.js`.

## 1. Problem statement

Deriv synthetic indices (e.g. R_10) publish a price tick roughly once per second. The **last digit** of the quoted price is the observable. A *Matches* contract with duration k ticks pays out if the last digit of the tick k steps after entry equals the chosen digit. LDPE forecasts a 10-class probability vector `p = (p0…p9)` for the last digit at horizon `h = k` (default 5, range 1–10), scores every forecast against its own target tick, and optionally trades the argmax digit when its probability exceeds a threshold.

**Null hypothesis.** Deriv states its synthetic indices are generated by a random process. If the last digit is i.i.d. uniform, no method can beat `p = 0.1`, and a Matches contract has negative expected value (payout is priced below fair odds). LDPE is therefore an *instrument for testing* whether any exploitable structure exists, not evidence that it does.

## 2. Data handling

- Digit extraction (`extractDigit`): taken from the quote string using the symbol's declared decimals; if the string's precision does not match, the digit is `null` and the tick is rejected (never guessed). Scientific notation and malformed strings are rejected.
- Per tick: duplicate, out-of-order, precision-mismatch and time-gap flags are recorded (gap = interval > 3× the median interval). Data-quality failure (gap rate > 20% after 50 ticks) suppresses trading.
- Warm-up: 100 ticks of model state are required before any forecast can be a TRADE.
- Buffer: up to 10,000 ticks retained; ticks are persisted (no credentials) and a reload reconstructs model state by deterministic replay, then reconciles with history backfill (overlap must be proven; otherwise the hole is recorded and the pending forecasts are marked unscorable).

## 3. Forecast lifecycle (no look-ahead)

For each accepted tick, in this order: (1) update counts with the tick; (2) score any pending forecast whose target tick is this tick; (3) emit a new forecast for tick `seq + h` using only information up to the current tick. Each forecast carries a unique id, its made-at and target sequence numbers, the full probability vectors, and is scored **exactly once** against its own target tick, independent of whether a trade was placed. Forecasts reconstructed during replay are flagged and can never trigger a trade.

## 4. Component models (each outputs a valid 10-vector)

All Dirichlet estimators use prior α = 1: `p_d = (c_d + α) / (n + 10α)`.

| Module | Description |
|---|---|
| uniform | Reference, p = 0.1 each. |
| dirichlet | All-history digit counts. |
| freqShort | Counts over last 50 ticks. |
| freqLong | Last 1,000 ticks, unsmoothed (+1e-6). |
| decayed | Exponentially decayed counts, half-life 300 ticks. |
| trans1 | First-order Markov: distribution of the digit at +h given the current digit (Dirichlet over observed (from→to at lag h) counts). |
| trans2 | Second-order: conditioned on the last two digits. |
| gap | For each digit d, empirical hit rate at +h conditional on "ticks since d last appeared" (bucketed, capped at 16), shrunk toward 0.1 with 20 pseudo-observations, renormalised. |
| streak | Distribution at +h conditional on (current digit, current same-digit run length, capped at 6). |

Any module returning an invalid vector is excluded for that forecast.

## 5. Ensemble and probability

1. **Weights** — exponentially-weighted (Hedge-style) on past performance. Each module keeps a decayed score `S_m ← ρ·S_m + (logloss_m − ln 10)` (ρ = 1 − 1/500, i.e. loss relative to uniform), updated only when its forecast is scored. Raw weights ∝ `exp(−η·S_m)` (η = 1), then projected onto the simplex with a floor of 0.01 and cap of 0.6 per module.
2. **Ensemble vector** `p_ens = Σ w_m · p_m`, renormalised and validated.
3. **Shrinkage vector** `p_final = λ·p_ens + (1−λ)·0.1`, where `λ = clamp((meanLoss_uniform − meanLoss_ens) / 0.02, 0, 1)` over the last 500 scored forecasts (needs ≥ 50). If the ensemble is not beating uniform, λ→0 and the forecast collapses to uniform.
4. **Calibration (optional, off the trading path by default)** — isotonic regression (pool-adjacent-violators) fitted on `(predicted probability, outcome indicator)` pairs from already-scored forecasts only, requires ≥ 300 scored forecasts, refit every 50, window 2,000. Out-of-sample log loss of calibrated vs raw is tracked and displayed; the trigger source can be `ensemble` (default), `shrunk` or `calibrated`.
5. **Prediction** — the argmax digit of the trigger-source vector (ties → lowest digit) and its probability.
6. **Trade decision** — `TRADE` only if: warm-up complete, data quality OK, no active structural break, calibration available (if that source is selected), reconstructed=false, and `p_top ≥ minProbability` (default 12%). Otherwise `SKIP` with a stated reason. The threshold is an operational setting, not a statistical claim.

## 6. Diagnostics

- **Mutual information** between digit(t) and digit(t+h) from the lag-h contingency table; bias-corrected (`MI − df/2N`), tested with `2N·MI ~ χ²(df)`, and suppressed below 500 samples.
- **Gap- and streak-conditioned frequencies** (displayed from the same tables the modules use).
- **Structural-break detection** — chi-square homogeneity test of the last 200 digits vs the preceding 800, every 10 ticks, at p < 1e-4 (deliberately conservative given repeated looks). Effects: trading ineligible for ≥ 100 ticks; half of every module's accumulated score is discarded once so weights re-adapt; already-scored outcomes are never rewritten. Cleared when p ≥ 1e-3 and the cooldown has passed.
- **Module disagreement** (Jensen–Shannon divergence across module vectors), entropy of the forecast.
- **Metrics** (prequential, out-of-sample by construction): log loss, Brier score, top-1 accuracy with a Wald 95% interval, each against the uniform baseline (log loss ln 10 = 2.3026; Brier 0.9; top-1 10%).

## 7. Execution (separate from prediction)

Orders go only through `exec.js` (the single order path). The user selects the Demo | Real account; there is no fallback to the other account on error. A Stop switch pauses automatic trading while forecasts continue to be generated and scored. Stake, cooldown (ticks) and stop-after-N are ordinary user settings. Stakes are rounded to 2 decimals. Duplicate orders are prevented across reconnects and repeated events; settlement updates are applied once.

## 8. Evidence to date (honest status)

- **Unit/integration tests**: 64 LDPE tests pass (engine, Tier 1 components, persistence/replay, executor, page bridge). These test correctness of the pipeline, not predictive skill.
- **Live-feed readout (R_10, ~9,100 scored forecasts, as displayed in the app)**: ensemble log loss 2.3033 vs uniform 2.3026 (Δ = +0.0007, i.e. marginally *worse* than uniform); Brier 0.9002 vs 0.9000; top-1 accuracy 10.6% (95% CI 10.0–11.2%) vs 10% — the interval includes 10%; mutual information (digit → digit+5) bias-corrected 0.0000 bits, p = 0.88; isotonic calibration worse out-of-sample than raw (2.3456 vs 2.3031); no structural break detected. **Interpretation: no statistically detectable predictive skill.** The 10.6% hit-rate is not significant against the null, and log loss/Brier do not beat uniform.
- A simulated (synthetic-data) evaluation is in `docs/ldpe-evaluation-simulated.txt`; it validates that the machinery behaves correctly under known structure and is not evidence about live markets.
- **Not verified**: no live Demo or Real contract results have been analysed for settlement-tick alignment between the configured duration and the forecast target tick. The earlier settlement-alignment gate was removed at the owner's instruction; alignment between the contract's actual settlement tick and the forecast target remains an unverified assumption.

## 9. Known limitations / questions for reviewers

1. If digits are i.i.d. uniform, every module estimates noise; the weighting scheme can only add variance. The shrinkage λ is designed to default to uniform in that case, but 0 or near-0 is the expected steady state.
2. Multiple-comparison control: 8 modules × 10 digits × thresholds, plus break tests every 10 ticks, with no family-wise correction beyond the conservative break p-value. Selecting a trigger threshold on the same data used for evaluation would be data snooping.
3. Hedge weights use a decayed loss window; the effective sample for weight selection is ~500 ticks, which is small relative to 8 competing modules.
4. The isotonic calibration map is fitted on overlapping (autocorrelated) horizon-h forecasts, so effective sample size is smaller than the count shown.
5. Top-1 interval is a Wald interval and treats overlapping forecasts as independent; a block bootstrap would be more appropriate.
6. Martingale-style stake progressions (available in the trade panel) do not change expectation; with a payout priced below fair odds, expected value per trade is negative regardless of stake sizing.
7. Recommended next evaluation: pre-registered, fixed-threshold, chronologically split out-of-sample test with a binomial test against 10% and a paired log-loss test against uniform (e.g. Diebold–Mariano with HAC variance).
